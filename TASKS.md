## Блок 4. Архитектура — ⛔️ НЕ В РАБОТЕ, задачи на потом

> **Ничего из этого блока сейчас не делаем.** Направление обсуждалось, но
> **не согласовано** — это черновик предложения, а не принятое решение.
> Не начинать без явного подтверждения пользователя.

Обсуждавшийся вариант: переезд на **Django + PostgreSQL + серверный рендеринг +
HTMX** на том же VPS. Основной аргумент — встроенная админка как замена Google
Sheets (владелец редактирует данные сам). Excel при этом остаётся как
импорт/экспорт через `django-import-export` с предпросмотром диффа, но
источником правды становится БД.

Открытые вопросы, которые надо решить ДО того, как этот блок вообще
превратится в задачи: оправдан ли переезд целиком (против точечных правок
текущего сайта), сроки, и не проще ли начать со страниц компаний (T-42) как
отдельного шага, не трогая остальное.

  на цикле. Значит проблема не только с бэкфиллом (старые посты) — сама
  привязка живого потока к каналу (`events.NewMessage(chats=sources)`)
  построена на этом же нерезолвящемся username, то есть и НОВЫЕ посты
  тоже не долетали никак. Пользователь подтвердил: канал реально
  переименовал публичную ссылку на @AutoLibraryChina, старый `bezpokrasa`
  просто освободился.

  **Почему не сделали простое переименование источника в конфиге.**
  Внутренний идентификатор "bezpokrasa" используется по всему файлу не
  только как адрес в Telegram, а как ключ бизнес-логики: `SOURCE_PARSERS`
  (`parse_china_invoice`), наценка `CHINA_MARKUP_RUB`, форматирование
  цены в `build_repost_text()`, вычистка построчной раскладки цены,
  `_condense_china_features()`, состояние отправленных постов (дедуп по
  `source_username`), история во всём TASKS.md. Просто заменить
  "bezpokrasa" -> "autolibrarychina" в `SOURCES` сломало бы всю эту
  логику (`SOURCE_PARSERS.get("autolibrarychina")` — None, парсер
  потерялся бы) и обесценило бы историю задач. Вместо этого — alias-слой:

  ```python
  SOURCE_TG_HANDLE = {"bezpokrasa": "autolibrarychina"}
  _TG_HANDLE_TO_SOURCE = {v: k for k, v in SOURCE_TG_HANDLE.items()}
  ```

  Внутренний `source_username` везде остаётся "bezpokrasa" (тот же
  бизнес/формат объявлений) — меняется только то, ПО КАКОМУ хендлу
  юзербот реально ищет канал в Telegram:
  - бэкфилл: `_collect_messages(client, SOURCE_TG_HANDLE.get(source, source), ...)`;
  - живой поток: подписка `events.NewMessage(chats=tg_chat_filters)` — по
    реальным текущим хендлам, а `on_new_message` переводит
    `event.chat.username` (текущий хендл, "autolibrarychina") ОБРАТНО во
    внутренний "bezpokrasa" через `_TG_HANDLE_TO_SOURCE`, прежде чем
    передать дальше в `handle_group()`;
  - очередь отложенных постов (`_pending_queue_flusher`): та же
    подстановка при повторном `client.get_messages(...)`.

  Если канал ещё раз сменит хендл — достаточно поправить одну строку
  (`SOURCE_TG_HANDLE`), вся остальная логика/история не затрагивается.

  **Проверено:** `py_compile` чисто. Логика alias'а прогнана вручную (не
  на живом Telegram — нет доступа к реальному API из этой среды):
  `SOURCE_TG_HANDLE.get("bezpokrasa", "bezpokrasa")` -> "autolibrarychina",
  `_TG_HANDLE_TO_SOURCE.get("autolibrarychina", "autolibrarychina")` ->
  "bezpokrasa" — соответствует ожидаемому поведению в обе стороны.

  **НЕ проверено:** на реальном Telegram-трафике (нужен реальный
  бэкфилл/живой пост из @AutoLibraryChina после деплоя — тогда будет
  видно, действительно ли резолвится канал и корректно ли доходит до
  `handle_group()` под именем "bezpokrasa", с правильным парсером/ценой).

  **Статус:** код готов, `py_compile`-чист, ждёт деплоя и реальной
  проверки на живом посте из @AutoLibraryChina.
