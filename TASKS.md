## Блок 2. Мобильная адаптация — текущий спринт

Сейчас на весь сайт **два** медиазапроса: `@media (max-width:720px)` на одну форму
(`:365`) и общий блок `@media (max-width:680px)` (`:403`). Блок писался
14.08.2026 реактивно — по конкретным багам, найденным скриншотами с iPhone.
Системы брейкпоинтов нет.

- [ ] **T-10. Единая сетка брейкпоинтов**
  Ввести 480 / 768 / 1024 вместо одинокого 680. Сейчас планшеты (768–1024) и
  узкие телефоны (≤380) не обработаны вообще: между 681px и десктопом
  раскладка едет.

- [ ] **T-11. На мобильном пропадают фильтры каталога**
  `index.html:406` — `.sidebar { display: none; }`. Вместе с сайдбаром с
  телефона исчезает фильтрация по направлениям (Китай/Корея/Япония…) — то есть
  главная функция каталога недоступна большинству посетителей.
  *Сделать:* фильтры в раскрывающуюся панель или горизонтальную ленту чипов
  над списком.
  *Приоритет: наивысший в блоке — это потеря функциональности, а не косметика.*

- [ ] **T-12. Инлайн-стили не дают адаптировать секции**
  `#contact`, `#customs`, `#blog` свёрстаны атрибутами `style="..."` с
  `grid-template-columns`. Инлайн выигрывает по specificity, поэтому мобильная
  правка уже потребовала `!important` (`:456`). Вынести в классы — иначе
  каждая следующая мобильная правка будет наращивать костыли.

- [ ] **T-13. Тач-таргеты меньше нормы**
  Ссылки нава на мобильном — 12px шрифт, кнопки `.nav-rate`/`.nav-tg` — паддинг
  6×12px. Норма — минимум 44×44px, иначе промахи по кнопкам.

- [ ] **T-14. 5.6 МБ автоплей-видео на мобильном трафике**
  `/videos/promo-bg.mp4` и `/videos/card-bg.mp4` по 2.8 МБ грузятся автоматически.
  Отключать на узких экранах либо `preload="none"` + `poster`-картинка.
  (Отдельно: `myavto.html:328` тянет `tanya_review.mp4` — 18 МБ.)

- [ ] **T-15. Изображения без размеров → скачет вёрстка**
  `nav-logo-full.png` и `hero-bg-logo-full.png` без `width`/`height` — layout
  shift при загрузке, портит Core Web Vitals. Плюс `hero-bg-logo-full.png`
  весит 185 КБ.

- [ ] **T-16. Шрифты грузятся с `fonts.googleapis.com`**
  Блокирующий внешний запрос на рендер; в рунете нестабилен. Положить локально
  или перейти на системный стек.

- [ ] **T-17. Живая проверка на реальных ширинах**
  После T-10…T-16 прогнать 320 / 375 / 414 / 768 / 1024 в браузере и убедиться,
  что горизонтальной прокрутки нет ни на одной. История проекта показывает, что
  этот класс багов ловится только живым прогоном, а не чтением кода
  (`PROJECT_STATE.md:2330`).
